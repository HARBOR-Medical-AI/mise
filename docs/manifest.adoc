== Status and purpose

This document designs the *manifest*: a plain text file that expresses a workflow — a PACS query, a cohort, a look at the images, a pipeline over the group — such that the same file runs headlessly in CI, runs at an operator's console, and *plays out visually* on the ARGUS surface for someone who was handed it.

It is a DESIGN document: the decisions below were grilled and settled on 2026-09-19, and nothing here is built yet. The build order is in <<build>>.

== Why

Three needs converge on one artefact.

*A test battery.* The repo's live gates are JavaScript exemplars and a CDP smoke suite. Neither reads like the work. A radiologist's actual workflow — query this accession, take the sagittals, pull them, run dcm2niix over the group — cannot be read off either, so the things that break in the field are not the things under test.

*Sharing.* A workflow that took an afternoon to get right is currently transmitted as a conversation. A manifest is a file: it lives in the ChRIS filesystem like any other, and it is shared by the same `setfacl` that shares a directory. Hand someone a path and they have the workflow.

*Demonstration.* Played at reading speed on the surface, a manifest is a demo that cannot drift from the product, because it is the product executing.

== The property that makes this cheap

ARGUS already obeys a law: a verb lowers to a line the operator could have typed. `PULL` on a row runs `pull`; `IMAGE` runs `image <path>`; the DELETE pill puts an `rm` in the transcript. And the kernel's commands emit typed models that the surface renders — `pacs query` fills the PACS pane, `image` opens a viewer, `cd` moves the browser.

Put those together and a file of kernel lines, fed to a session with a surface attached, *already plays out visually*. There is no second execution path to build, no driver, no selector language, and no way for the script and the product to disagree — the script IS the product's own vocabulary. The "in a way similar to playwright" ask is answered without Playwright's central cost: Playwright drives a surface from outside, through a model of the DOM that rots; a manifest drives the *session*, and the surface renders it for the same reason it renders a press.

== Settled decisions

[cols="1,3"]
|===
| Manifest form | *Plain kernel lines.* A manifest is a text file of the exact lines an operator would type, with `#` comments and a small `@` header. Not YAML, not a step object model — a second language beside the kernel's would have to be kept in step with it forever, and that is the thing that drifts.

| Self-checking | *`expect` is a kernel verb*, not an external harness and not an enforced comment. A manifest asserts wherever it is played — CI, your console, someone else's browser — so a shared workflow tells its new owner whether it ran right, not merely that it ran.

| Time | *Verbs block by default; `--detach` opts out.* A manifest line means what the operator's line means, so the blocking cannot live only in the runner. No sleeps exist anywhere in the language.

| The lane | *A blocking verb holds its own line, never the session.* It annunciates progress on the progress channel while it waits (the heartbeat already pushes while busy), other panes keep refreshing, and Esc detaches it — printing the handle and returning, which is today's behaviour, on demand. The law _index-movement never holds the lane_ stands.

| Cohort identity | *A path, always.* `gather add <path>` — series, directory and file are all paths, dedupe is by path, and it wears a shell metaphor as the law asks. Unpulled PACS series already have a projection path, so nothing is a special case. Kind, imagery, study and counts are looked up when listed, never stored.

| Cohort truth | *The kernel owns it and annunciates; the surface subscribes.* `gather` emits on a channel the way `feed.created` does. A manifest line, a console line and a press on a row all reach the header band by one route — which is precisely what makes a manifest play rather than run invisibly.

| Authoring | *Record the session.* `record start <file>` … `record stop` writes every line the session ran, typed or minted by a press, and offers `@param` placeholders for the literals that look like identifiers. The workflows worth sharing are the fiddly ones nobody will retype correctly.

| Placement | *A manifest never names a pane.* No splits, no zoom, no pane ids, no "click row 3". It says what to do; the surface places the result by the same rules it uses for a press. One file therefore plays identically on a headless `chell` and in a browser, and a recording made in ARGUS is runnable in CI. See <<shared>> for why view state is nonetheless reachable — it is regard, not placement.
|===

== The language

=== Shape

A manifest is UTF-8 text. One line, one kernel command. Blank lines and `#` comments are ignored. Lines beginning `@` in the header declare metadata. The conventional extension is `.mise` and the conventional home is `~/flows/` on the ChRIS filesystem, so a manifest is shared, versioned and ACL'd like any other file.

[source]
----
@name         sagittal cohort for one patient
@description  Query PACS for a patient, take the sagittals, pull them, look at one.
@param        MRN
@param        LABEL  = sag cohort

pacs query PatientID:${MRN}
expect pacs series gt 0
----

`@param NAME` declares a required parameter; `@param NAME = value` gives it a default. Play refuses before running a single line if a required parameter was not supplied — a manifest never gets half way in and then asks.

=== Substitution

Substitution is not the manifest's: it belongs to the session, and every line gets it — typed at a console, played from a file, or minted by a press. One expander, owned by the tokenizer, so quoting is still known when it runs:

* A *bare* reference carrying several values becomes several operands: `pull ${gather}` pulls each member, whatever spaces and brackets their paths hold.
* A *double-quoted* reference stays one operand however many values it holds.
* A *single-quoted* `$` is text, as in any shell — which is what makes a JSON blob or a tag list safe to pass through.
* An expanded value never globs afterwards: a filename with a bracket in it is a filename, not a pattern.
* The *command word* expands too, so a manifest can name its plugin as a parameter and the same workflow runs on an instance with different builds.

A row of the last answer is named by its handle, which says WHAT it counts: `@SER3`, `@STD001`, `@FIL2,3,7`, `@DIR2-4`. A bare number is not an index — it said nothing about what it counted, and in a PACS answer every study read "1", being the only study under its patient. One sequence per kind runs across the whole answer, so a handle is a name rather than a position and a sorted listing does not renumber it. Zero padding is how the pill draws it, not something to type. What is numbered is the most recent ANSWER of the surface the line came from — the model, not any rendering of it, so a console table and a graphical pane count the same rows. Each surface keeps its own: a listing read in a browser does not renumber the rows a console is about to act on, and a terminal a surface shows counts as that surface. The line that acts on a handle says which listing it counted. A handle past the end of its kind refuses and says how many of that kind there are; `'@SER2'` in quotes is text, and `user@host` is not an index because only a handle at the START of a word is one.

What a row hands over differs by kind: a series its path; a file or folder its path; a STUDY its series, which is what the surface's GATHER on a study hands over, so `gather add @STD001` and `pull @STD001` act on the whole study. A verb refuses a kind it does not take, by name and at expansion: `image @STD001` says "image takes a series or a folder or a file; STD001 is a study" rather than resolving to a path and failing three steps later for a reason that names nothing typed.

Three sources answer, in order: the session's *built-ins* (its reserved names, read-only), then *variables* (what a line set with `NAME=$(command)` or `NAME=word`, and inside a play the manifest's parameters, read-only), then the *environment*. A variable holds the command's answer, its model, not its printed text: `${A.instanceId}` is a field of that model by the name the model gives it, a field holding a list reaches through it one operand per element, and a bare `${A}` is its rows or refuses by name when the answer is one thing with several fields (issue #1208). A bare `${A}` gives the operands a pipe would hand on: a listing's leaf rows, each once, never the patient or study rows a filter kept as context. Written as an argument a variable becomes words; standing alone at the head of a pipe it hands on its model, as the command that made it would: `${T1} | grep -i sag | gather add` (issue #1226). A manifest that declares a `@param` with a reserved name is refused when the file is read, because `${gather}` meaning two things is a language with a hole in it.

A reference nothing answers *refuses the line* — it does not expand to nothing and does not stand as text. `rm -rf ${DIR}/scratch` with `DIR` unset is how a script deletes the wrong thing. The refusal names the reference and where it looked. The single exception is a dry run, which has run nothing and so leaves a reference to what a later line would produce standing as written.

A manifest names what its own lines made: `A=$(pl-dcm2niix-v1.0.2)` holds that run's answer (`instanceId`, `feedId`, `newFeed`, `outputPath`, `status`), and `${A.outputPath}` is where it wrote. A failed command fails its line and leaves the name as it was, so the play stops there. `@answers NAME` declares what the manifest hands back: `X=$(play f)` holds that variable's model, and a play that ends without setting it is refused. Beyond what it names itself, a manifest reads session truth through a few *built-ins*, read-only, each a thing the kernel already holds:

[cols="1,3"]
|===
| `${gather}` | The cohort, as an operand list, each member at the address it was GATHERED FROM — what `pull` takes.
| `${gather.series.folderPath}` | Where each member LANDED in CUBE — what `image` and a run take. A member has two addresses and the difference is load-bearing; this refuses by name when a member is not in CUBE yet.
| `${gather.name}` | Any field of the cohort as `gather` answers it, by the field rule every variable follows: `${gather.feed.id}`, `${gather.series.modality}`. `${gather}` is read live on every use. One member is named by an `@` handle, never by an index.
| `${listing}` | The held listing's rows as it stands.
| `${cwd}` | The session's working directory.
|===

The pronouns that came before variables (`${feed}`, `${run}`, `${run.place}`, `${query}`) were filled behind the line by whatever ran last, so one name meant one run on one line and another four lines later, and a path that forgot to fill one left it stale (#1207). They are gone; a line names what it means.

=== A decision is a data state, never a branch

A manifest is a straight line of kernel lines. It has no `if`, `for`, `while` or `case`, no `&&` or `||`, no `test`, arithmetic or string slicing. This is the ChRIS feed's own design: a feed has no conditional edges; a decision is a node whose output is the chosen data, and what runs downstream works on what came out. In a manifest the same parts are selection (`grep` on a listing, `gather add`: a step whose answer is the decision), assertion (`expect`, whose only outcomes are go on or stop), and verbs that take many operands (the iteration lives in the verb, as in `gather process`). A capture names a node's state, and holding it as a snapshot matches a finished node's immutability.

What this keeps: `--dry-run` shows every line that will run; `record` can produce any manifest; a shared manifest reads top to bottom.

What it rules out includes the small steps that look harmless: `X=$(…) || Y=$(…)`, `$(…)` as an operand, a predicate inside the dots (`${G.series[modality=MR]}`), `expect --else`. A need that wants one becomes a verb or a node whose output encodes the decision (a filter on the verb, a filter plugin), or a program against the typed chell API. A program is not a manifest.

The analogy has a limit. A feed is run by CUBE and pfcon: in parallel, scheduled, persisted, with provenance. A manifest is run by the kernel: in one session, in one total order, with variables that end with the process, and with steps that are not data (`cd`, `gather add`, `pull`, `feed rm`, `expect`). A manifest does not compile to a pipeline.

=== expect

[source]
----
expect <subject> <property> <predicate> <value> [--within <duration>]
----

Subjects are the kernel's own. Predicates are `eq`, `ne`, `gt`, `gte`, `lt`, `lte`, `contains`, `notContains` and `matches`. With `--within`, `expect` polls until the claim holds or the deadline passes — `expect` is the only verb in the language that knows about time.

[cols="1,3"]
|===
| `gather size\|pulled\|name` | The cohort. A member counts as home once CUBE has said where it landed; a gathered place was never anywhere else.
| `feed <id> status` | A feed, as this session has indexed it.
| `run <instance-id> status` | One plugin instance, asked of CUBE.
| `path <p> exists` | Whether a path is there.
| `path <p> count [--matching <glob>] [--deep]` | How many things a folder holds. `--deep` looks beneath it: a plugin files its output in a tree (pfdicom writes under `share/incoming/<input tree>`), so a claim made at the node's own folder would otherwise be false about a run that worked.
| `path <p> tags <TagName>` | What a DICOM header says, looking beneath the path when the folder itself holds none. A tag that VARIES across the folder answers with every value it takes, so a claim about "the" value cannot pass by reading only the first file — which is what makes this the honest check on an anonymization.
|===

The subject a manifest most wants — `pacs`, for "the query answered something" — is not built: a query's answer is asserted through the path it wrote, or captured (`Q=$(pacs query …)`) and read by its fields.

A satisfied expectation prints one confirming line. A failed one prints what it wanted, what it got, and where it was standing, then refuses: play stops at the first refusal (a manifest is a workflow, and the second half of a workflow whose first half failed is noise), and the process exits non-zero.

[source]
----
expect gather size eq 14
expect feed status eq finishedSuccessfully --within 20m

  ✗ expect gather size eq 14
      wanted  14
      got     11
      at      flows/sag-cohort.mise:9
      cohort  11 series · 1 place
----

=== play

[source]
----
play <manifest> [--param K=V]… [--pace <duration>] [--step] [--dry-run] [--status]
----

`play` reads the file through the VFS and runs its lines in order against the current session. Nothing is special about the execution: each line goes through the same path a typed line goes through, so every attached surface renders each step as it lands.

A play gives back the working directory it began in when it ends: the last line, a refused line that stopped it, a `--pace` stop, an interrupt. The session is shared by every surface attached to it, so a manifest that does `cd ${FEED.path}` to run a pipeline from that node must not leave them all standing inside the feed. Within the play the `cd` holds as usual. A `--dry-run` runs no line and moves nothing (#1264).

`--status` runs no line either: each is expanded as a dry run expands it, and the verb it begins with says, from what the backend keeps and never from the cloud, where it stands. Four states: *not yet* (what it stands on is missing, and the line that would supply it), *ready*, *done* (the line replays to unchanged or nothing to do), *changed* (what it built moved under it, so a replay plans and asks). One row per line, a count at the end, and a `manifest.status` model a surface reads; a verb that keeps nothing reads as a dash. stratus answers for `net`, `vm` and `chris` (docs/stratus.adoc, D17).

`--pace` puts a delay between lines, for watching. `--dry-run` expands parameters and variables and prints the lines it would run without running them — the manifest's `--help`; a reference an earlier line WOULD have set or changed stands as written, since nothing has run to give it a value: a variable the manifest assigns, `${gather}` past a `gather` or `pull`, `${cwd}` past a `cd`, an `@` index or `${listing}` past any line. The session could answer those from what it held before the play, and that answer would name the wrong things. A capture `NAME=$(…)` is shown around the command it holds, as the session reads it. `@answers` is shown as written. `--step` is refused by name: a keypress needs a terminal and a daemon has none, so at a surface the answer is `--pace`.

A manifest is read from the ChRIS filesystem — that is what makes one shareable, and sharing it is `setfacl`, like any other file. A path that names no CFS file is then looked for on the disk the ENGINE runs on, which is how a repository's battery runs without uploading itself first; in a daemon that disk is the daemon's, never the surface's, which is why CFS is asked first.

`play` is itself a kernel verb, so a manifest may play another manifest. One level of nesting is expected (a battery that plays its cases); recursion is refused by name.

=== record

[source]
----
record start <manifest>
record stop
----

Between them, every line the session runs is appended — typed at the console, or minted by a press on the surface, which is the same thing by law. On `stop` the recorder reads back what it captured and offers parameters for the literals that look like identifiers (an MRN, an accession, a feed name), so the file is shareable rather than personal:

[source]
----
record stop
  wrote ~/flows/sag-cohort.mise · 6 lines
  offered 1 param:  PatientID:1279049  →  ${MRN}
----

What is recorded is what the session did. Expectations are not inferred — a recording is a faithful transcript, and a transcript that guessed at assertions would be a fiction. Adding `expect` lines is the author's act, and it is the act that turns a recording into a test.

== Worked examples

=== The cohort workflow

The workflow under discussion: query PACS, take some series, look at one, process the group.

[source]
----
@name         sagittal cohort for one patient
@description  Query a patient, gather the sagittal series, pull them, view one, convert the group.
@param        MRN
@param        LABEL = sag cohort

# Ask the PACS. Blocks until the answer is in; the surface fills its PACS pane.
pacs query PatientID:${MRN}
expect pacs series gt 0

# Take the sagittals. --shown takes what the filter shows, which is what the operator sees.
pacs filter sag
gather add --shown
expect gather size gt 0

# Bring them home. Blocks until the retrieve settles; the surface's badges turn as each lands.
pull ${gather}
expect gather unpulled eq 0

# Look at one before committing the group to compute.
image @SER1

# Process the cohort as a group: one feed whose root holds every member, one run over it.
R=$(gather process pl-dcm2niix-v1.0.2 --title "${LABEL}")
expect run ${R.instanceId} status eq finishedSuccessfully --within 20m
----

NOTE: The examples are written in the finished language. `pacs filter`, `gather add --shown`, `gather process`, and the `pacs` and `gather unpulled` subjects of `expect` are not built yet.

Played in ARGUS, an observer sees: the PACS pane fill; the filter narrow it; the header band's `01-GATHER` face count up; the badges turn as the retrieve lands; a viewer open on the first series; the catalogue compose the run; and `RUNS-02` take the new feed. Played headlessly, the same file prints envelopes and exits 0 or non-zero. Neither run knows which it is.

=== Pull, anonymize, convert to NIfTI

The de-identification workflow, where the expectations carry real weight: a manifest that converts without asserting the anonymization ran is worse than no manifest.

[source]
----
@name         anonymize and convert
@description  Pull a study from PACS, strip identifying tags, convert to NIfTI, keep the result.
@param        ACC
@param        SUBJECT                       # the pseudonym the data will carry downstream
@param        LABEL   = anon-nii

pacs query AccessionNumber:${ACC}
expect pacs studies eq 1                    # an accession is one study, or the manifest is wrong about the world

gather clear
gather add --shown
expect gather size gt 0

pull ${gather}
expect gather unpulled eq 0

# Strip the identifying elements. The tag list is named here because a
# manifest that anonymizes should say what it changed. DOUBLE quotes: a
# reference inside single quotes is text, as in any shell.
cd ${gather.series.folderPath}
A=$(pl-pfdicom_tagSub-v3.3.4 --fileFilter dcm --tagInfo "PatientName,${SUBJECT}++PatientID,${SUBJECT}++AccessionNumber,anon++PatientBirthDate,19000101" -- feed_title="${LABEL}")
expect run ${A.instanceId} status eq finishedSuccessfully

# Prove it, on the data, not on the plugin's word.
expect path ${A.outputPath} tags PatientID eq ${SUBJECT}
expect path ${A.outputPath} tags PatientName notContains ${ACC}

# Convert the anonymized output, never the input.
cd ${A.outputPath}
C=$(pl-dcm2niix-v1.0.2)
expect run ${C.instanceId} status eq finishedSuccessfully
expect path ${C.outputPath} count --matching "*.nii*" --deep gt 0

# Look at what came out, and keep it.
image ${C.outputPath}
----

Two things are deliberate. The conversion runs on the anonymization's output node, not on the feed root, so the manifest cannot silently convert identified data. And the anonymization is asserted by reading tags back off the produced files — the one check that survives a plugin changing behind you.

NOTE: the flag spellings are the live plugin's, confirmed against a running store: `pl-pfdicom_tagSub` takes `--fileFilter` and `--tagInfo` (pairs split on `++`, key and value on `,`), not the `--extension`/`--splitToken` an earlier draft of this document guessed at. The versions are this instance's; a manifest names them as parameters so another instance can supply its own.

=== A battery case

A CI case is a manifest with the fixture baked in and the expectations tight. Batteries are manifests that play manifests.

[source]
----
@name  battery · cohort
@description  The cohort workflow against the known fixture, at full speed.

play ~/flows/sag-cohort.mise --param MRN=1279049 --param LABEL="battery sag"
play ~/flows/anonymize-nii.mise --param ACC=22119730 --param SUBJECT=anon-001
----

Run headlessly, this is `chell -c 'play ~/flows/battery.mise'`, and its exit status is the gate. Run in a browser with `--pace 2s`, it is the demo. There is one file.

== What plays, and what does not

A manifest can say anything the session can do, which is a great deal: navigate, query, gather, pull, run, view, share, delete. It cannot say where the result goes, because placement is the surface's judgment and encoding it would fork the file into a browser version and a headless version.

The consequence to be honest about: a manifest cannot currently assert anything about the *look* — that the frame opened, that the verbs lit, that the layout held. That is the smoke suite's job, and it stays the smoke suite's job. The two meet at the seam where a manifest is the smoke suite's setup: a scenario that needs a cohort on the band gets one by playing four lines instead of by re-implementing them in CDP.

== Shared sessions

A live shared session — two radiologists on one image, same slice, same window level, in real time — is the same machinery seen from another angle, and it is worth stating how they meet because the design should not foreclose it.

A manifest is a *recording* of intents replayed into a session. A shared session is a *stream* of intents mirrored between sessions. AEGIS already carries the parts: `regard` is a session subject in brasa — what the operator indicates, as an address plus model kind — it rides a push channel, calypso already retains and rebroadcasts it with late-attach replay, and a slaved viewer already follows it. A second surface attached to one session therefore already sees what the first one regards.

What is missing for two radiologists is not a protocol but a *subject*: the image pane's view state — layout, slice, window/level, colormap — exists today as `state_get` on the pane (the dormant-group snapshot reads it) but lives only in that surface's memory. Promote it to a session subject beside regard, and following becomes subscription. That is one subject away, and the manifest work pays for the route it travels on.

This also explains why view state is *not* a violation of the placement rule. `image ${path}` says what to look at; a future `regard slice 42` would say what is being indicated *within* it. Both are session truth, both are things an operator does, both are recordable and replayable. "Open a pane to the left and zoom it" is none of those things — it is furniture, and furniture stays out.

Not settled, and deliberately out of scope here: whether a shared session is symmetric (both may write regard) or has a driver and passengers; what the second radiologist's identity is to CUBE; and whether a session is shared by ACL on something, the way a file is. The manifest design commits to none of these.

== Open questions

* *Where `expect path … tags` gets its answer.* Reading a tag back is `dcm tags` over a path; whether `expect` calls that or grows its own accessor is a build decision, not a design one.
* *Cohort membership after a pull.* A member's path changes when it comes home. Path identity says a pulled member *updates* rather than doubling, and `gather pulled` counts members that are in CUBE — the mechanism that rewrites the member's path needs a slice of its own.
* *Parameter typing.* `@param MRN` is untyped today. A manifest handed to someone else would benefit from `@param MRN : mrn` so play can refuse a malformed operand before touching the PACS, but no typed-operand vocabulary exists yet.
* *Secrets.* Nothing in these workflows needs a credential, because the session is already authenticated. A manifest must never grow a way to carry one.
* *Recording fidelity across a restart.* `record` follows the session; a daemon restart mid-recording ends it. Whether it resumes or refuses is open.
* *Yielding the lane while waiting.* The blocking verbs hold their own line and annunciate progress, and Esc detaches. A waiting command gives up what it holds, and a read runs beside a writer (calypso.adoc, #1273), but a blocking verb that has not said what it changes still holds the whole session against other writers while it works; a long run is best started with `--detach` when the session has other writing to do.

== Build order

Each slice is shippable and verifiable on its own.

. *`gather` as a kernel subject.* `gather list|add|remove|clear|name` over the session file the surface writes today, path-identified. No manifest yet — this alone makes the cohort scriptable. `gather process` waits for a `run` that blocks (slices 2 and 3), because a process verb that returns before its feed exists cannot be asserted on; the `gather.changed` annunciation and the header band's subscription follow in a slice of their own, so the surface changes hands only once the kernel's cohort is proven.
. *Blocking verbs.* `pull` and `run` block their own line with progress on the progress channel, `--detach` restores today's behaviour, Esc detaches live. The law about the lane gets its enforcement.
. *`expect`.* The subject/property/predicate grammar, `--within`, the failure readout, the exit status.
. *`play`.* Header parsing, parameters, variables (#1208), `--pace`, `--step`, `--dry-run`, refusal on a missing parameter, one level of nesting.
. *`record`.* Capture of typed and minted lines, parameter offering, write to CFS.
. *The first battery.* Built, as `packages/chell/exemplars/flows/`: `00_session.mise`, `10_anonymize_nii.mise` (anonymize, prove it on the produced files, convert, remove the feed) and `battery.mise`, whose exit status is the gate. The exemplars README's standing caveat — "static scripts cannot capture ids between commands, so the full feed+dcm2niix workflow is TS-only" — no longer holds.

A surface decision lands in `apps/argus/docs/aegis.adoc` in the same PR as the slice that makes it, per the standing law; slices 1, 2 and 4 each carry one.
