ChRIS settings are a listing you edit in place, and a user's password is set in that user's own row. On CHRIS, COMPUTE, HOST and PORTER are rows of FIELD · SET TO · RUNS: a press edits the value where it stands, a value the engine would refuse is marked and never kept, and a row that differs from what runs is marked. In ITS USERS a row's editor takes NEW PASSWORD and RETYPE (masked, matched as typed) or GENERATE (shown once), and one SET PASSWORD button sets it: no question for an ordinary account, one in the row for `chris` because CUBE restarts. The screen answers the engine's hidden questions itself, so the password never reaches a command line, the log or the strip; the receipt stands in the row. APPLY now carries email and groups only. When nothing differs from what runs, CHRIS, SPEC and SERVICES say so in one quiet line instead of a change block; CHRIS keeps a small REPLAY there that still asks before it restarts anything.
