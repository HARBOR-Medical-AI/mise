A machine's controls offer only what can be done, and its ChRIS's profiles and users are listings you edit in place. On a machine that stands the disk and data sliders and boxes start at what runs (ONLY GROWS) and the OS is fixed; ADD SERVICE offers only kinds and ports that can be added and says why on itself (22 is SSH, a port open already, a name or key it cannot take). CHRIS lists every profile stratus knows with what it puts up and what it needs: MINIMAL can be chosen, COMPLETE is shown as not built yet. ITS USERS lists CUBE's accounts with their UID, GID, groups and email (the password never shown); a new user is a new row, groups are chosen from the ones CUBE holds, and every edit collects into one change block whose APPLY runs each in turn, the engine asking each. `chris user add` takes `--groups`, the new `chris user mod` changes an account's email or groups, and `chris status` reads each account's id and groups. A change only the engine refuses is listed with its reason and left out while the act carries the rest; the note under a button stands only while it can be pressed.
