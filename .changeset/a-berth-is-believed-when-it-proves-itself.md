A session's berth sits in a folder only its owner can use, and counts only when its daemon proves it wrote it. Without a runtime directory the folder is `<tmpdir>/calypso-<uid>`; folders and records are held to this account (no link, no other owner, nothing wider than 0700/0600) and written by rename, never through a planted link. Each launch writes a probe key into its record and answers `GET /instance?nonce=` with an HMAC proof over its identity, pid and boot time; the discovery request carries no token, and a client attaches only to a record whose daemon proved itself. A daemon of an earlier release cannot prove itself: it is listed as unverified, and neither chell, calypso nor porter starts or adopts beside it. Stop such a daemon once (Ctrl-C at its idle prompt, or its service manager) and start it again. No process removes a berth or the attach note; the next daemon replaces them. The attach note holds no token or attach command any more, only the identity and `calypso --berths`, which gives both for a daemon that proves it is running. Porter refuses to serve, adopt, list or end sessions when its state root's path passes through a folder another account can write (a lab home's `775` `~/.local/state`, say), naming the folder: take group and other write off it, or set `PORTER_STATE_DIR` to a folder on a trusted path (sessions under the old root are not moved). Check with the new porter's `--status` before switching a host over (`docs/porter.adoc`). The unused `discovery_*` exports are removed, along with `berth_remove`, `berthUrl_isAlive` and chell's `berth_probeLive`.
