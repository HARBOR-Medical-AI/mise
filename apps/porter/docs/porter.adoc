== Abstract

PORTER is to ARGUS what gdm is to a desktop: the thing that logs a human in, finds or starts their session, and shows them to the surface. It is not a surface (it attaches to nothing) and not the session (calypso is); it is the door. This document is its design log, kept the way `apps/argus/docs/aegis.adoc` keeps ARGUS's: every decision lands here in the pull request that makes it.

== Status

Grilled and settled 2026-09-21; built in slices from that day. Tier 2 of link:../../../docs/session-supervisor.adoc[the session supervisor] — the porter that document reserved a name for in 2026-07, arriving now that the web surface exists.

The porter stands the new boot record first (so a greeter following `/boot/<key>` never sees a gap that reads as "up"). It leaves the old daemon the reason beside its berth (`closing-<key>.json`, cause `restart`) and SIGTERMs it, then waits until it is gone: its child has exited, or its berth stops answering. The operator's password is never asked again. A refused saved token ends the boot failed with the reason, and the greeter offers BACK TO THE DOOR. On SIGTERM the daemon reads the reason (or says `stop`) and sends `closing` to every surface before it exits, so a remote chell prints why instead of "disconnected". `porter --end` leaves `end`. Proved live on a private porter that adopted a daemon booted on `--saved-token`: the restart's boot stream, a new pid, the mount answering again, and the attached chell's goodbye. |

No attach token reaches the terminal, exactly as none reaches a browser. This is the levelling AEGIS asks for at the door: one login, one session, one set of rules, whichever surface comes. |
| 2026-09-21 (a session outlives its door) | Slice 6, the lifecycle. Three facts settled the shape. A session outlives every surface on it, and now the porter too: a porter that restarts ADOPTS the sessions its predecessor started — it reads every berth under its state directory, keeps the ones that answer, and the daemon's pid now rides in its berth (calypso) so an adopted session can still be ended. Idle is a span with no wire open and nothing through the door: the registry counts the relayed WebSockets on each session and notes each proxied request, and a sweep every minute ends what has stood idle longer than `PORTER_IDLE_HOURS` (a day, the same as the cookie) — the process only, never the state directory, so the next login boots warm. `porter --status` lists what the state directory holds and whether each answers. The state directory is precious and lives on real disk (`/var/lib/porter`): every identity's first login on a host is a cold boot against CUBE; every later one boots warm from the directory, which is the whole cost model of the porter. |

A person at the door is logging in to ChRIS; the name of the program at the door is this repository's business. | 2026-09-21 (the greeter) | Slice 5. The operator's first login through the door hung the browser for a minute with nothing to look at: `POST /login` waited for the berth. Now the door answers at once. The login page wears the same shell with the brain at rest. The cold boot itself is unchanged and is the cost of a fresh state directory — the first login per identity per host; every later one boots warm or attaches. |
| 2026-09-21 (the door itself) | Slice 4. `GET /login` is the plainest page that can ask for a name and a password, and the greeter will take its place without moving the route. `POST /login` takes the form or JSON; on a token it sets a SIGNED cookie naming the session's key — HttpOnly, SameSite=Lax, Secure when a front said the page came over TLS (`trustProxy`), a day long by default (`PORTER_COOKIE_HOURS`), the same span an idle session lives, since CUBE's tokens carry no expiry to follow — and sends the browser to `/s/<key>/?door`; a refusal sends the form back to the door with the reason in the query, and a JSON caller gets the status. The cookie gates `/boot/<key>`, `/s/<key>/…` and the upgrade: a browser reaches only the session its cookie names, a request with none is sent to the door (302), a boot ask without it is refused (401), an upgrade without it is dropped before a byte reaches the daemon. `POST /logout` clears the cookie and touches the session not at all — a daemon outlives every surface, eviction decides when it ends, and a LOG OUT that killed the session would make the next login a cold boot. The signing secret is `PORTER_SECRET`, at least twenty characters; given none the porter makes one up per start and says so, and every browser is asked again at a restart. The root `/` sends a browser let in to its session and anyone else to the door. In argus the LOG OUT pill stands only on a page that came through a door and leaves by it (`apps/argus/docs/aegis.adoc`, a-surface-leaves-by-the-door-it-came-in). With the gate in place the porter may listen beyond loopback, behind TLS. |

The session is mounted at `/s/<key>/`, the key being calypso's berth key for the identity — sixteen hex characters, stable across porter restarts, carrying no URL of anyone's into the URL bar. Under the mount the page, its assets and `/vfs` are proxied to the daemon on loopback, the attach token put on the proxied `/vfs` query and the proxied upgrade URL by the porter (calypso reads it there since this slice); the browser holds no token and is sent to `…/?door`. `GET /boot/<key>` is the session's boot as server-sent events — one per line the daemon wrote, ANSI and all, replayed for a late attacher — ending in `ready` or `failed`: the greeter's feed, and the same text the terminal boot shows. Every login re-checks the password at CUBE even when the session is up: a berth proves the daemon, not the human.

TLS external — caddy or nginx on titan, an Ingress on argentum; the porter trusts `X-Forwarded-Proto` and never terminates. The greeter shows the SAME boot the terminal shows: the ASCII brain (`@fnndsc/menu/logo`, paced by the greeter) beside the boot rows off the daemon's stdout. No `--host-control` on titan, where every session shares one uid; it returns with pods, where a shell in one's own container is one's own. A relayed WebSocket that fails does the same repair, so the surface's own reconnect lands on the live daemon.

== Routes

[cols="1,3",options="header"]
|===
| Route | What it does
| `GET /healthz` | The CUBE this door serves and how many sessions it knows.
| `GET /` | To the session the cookie names (`/s/<key>/?door`), else to `/login`.
| `GET /login` | The door: the brain at rest, username and password.
| `POST /login` | Form or JSON `{username, password}`. Sets the cookie and answers at once. Form: 303 to `/s/<key>/?door` when the session is up, to `/greet/<key>` when it must boot, or back to `/login?reason=…`. JSON: `{key, mount, state}` (`attached` or `starting`); 401 with CUBE's word.
| `GET /greet/<key>` | Cookie-gated. The greeter: the brain awake, the boot rows arriving, the hand-off to the session on `ready`.
| `GET /greeter/brain.js`, `/greeter/ansi.js` | The wire package's own modules, served from where it is installed.
| `POST /restart` | Cookie-gated: the cookie's own session, and no other. The old daemon is left the cause (`restart`) and ended, and the boot's first line says why in plain words (`Restarting a stale calypso daemon (brasa 0.31.5 → 0.33.0)` when the door ships newer code, `Restarting the calypso daemon, as asked` on RESTART); a fresh one boots on the login the session saved (`chell --saved-token`); the browser follows the boot on the greeter. The mount refuses until the fresh berth answers. A second press while it boots joins that boot. Form: 303 to `/greet/<key>`. JSON: `{key, greet, state: 'restarting'}`; 401 for a browser that holds no session.
| `POST /logout` | Clears the cookie; the session lives on. Form: 303 to `/login`. JSON: `{ok: true}`.
| `POST /login` with `Authorization: Bearer <door token>` | A script's way in: no body. The token's identity is let in as a password would be; a session not up boots on the login it saved. The JSON answer carries `user`, `tokenName`, `expires`. An expired or unknown token is refused by name (401).
| `POST /login` JSON with `tokenName` | A password login asking for a door token beside its session: the answer carries `token: {token, name, expires}`, the plaintext shown this once.
| `POST /auth/device` | `{host}`: a one-time code for a chell on that host (`chell auth login`). Answers `{code, expires, url}`; the code lives ten minutes and is taken once.
| `GET /login?code=<code>` | The login page saying what it is for: "Authorise chell on <host>". The form carries the code; a password login with it mints a token named `<user>@<host>` and hands it to the waiting poll.
| `GET /auth/device/<code>` | Chell's poll: `{state: pending}`, then `{state: authorised, token, user, name, expires}` once, then 404.
| `GET /auth/tokens` | Bearer-gated: the identity's own tokens (`name`, `created`, `expires`, `lastUsed`), what `chell auth tokens` reads.
| `DELETE /auth/token` | Bearer-gated: revokes the token in hand, what `chell auth logout` calls.
| `GET /berths` | For the operator, asked with `Authorization: Token <CUBE token>` or Basic credentials, which porter hands to CUBE to verify; only a CUBE administrator is answered (401 with none or ones CUBE refuses, 403 for a CUBE user who is not an administrator, 502 when CUBE or the launcher does not answer). `{at, berths: [{user, state, cohort, cpuPercent, memoryBytes, memoryLimitBytes}]}`: a running berth with one sample of what it uses, a stopped one as the home kept (usage null); a person with neither is absent. A porter that starts no berths answers `{berths: null, why}`. Credentials are never logged or echoed.
| `GET /boot/<key>` | Cookie-gated (401). Server-sent events: `line` (`{channel, text}`), then `ready` or `failed` (`{reason}`).
| `/s/<key>/…` | Cookie-gated (302 to `/login`; an upgrade without it is dropped). The session: page, assets, `/vfs`, and the WebSocket wire, proxied to that identity's daemon on loopback with the token added by the porter.
|===

== Configuration

Environment only, read once at start.

[cols="1,3",options="header"]
|===
| Variable | Meaning
| `PORTER_CUBE_URL` | Required. The one CUBE this door serves, API base (a trailing slash is added).
| `PORTER_STATE_DIR` | Where each identity's `config`, `run`, `cache`, `tmp` live. Default `$XDG_STATE_HOME/porter`, else `~/.local/state/porter`.
| `PORTER_HOST`, `PORTER_PORT` | Bind address; default `127.0.0.1:4180`.
| `PORTER_CHELL` | The chell entry to start sessions with; default the `@fnndsc/chell` installed beside the porter.
| `PORTER_SECRET` | What the cookie is signed with, at least twenty characters. Given none, one is made up per start and every browser is asked again at a restart.
| `PORTER_COOKIE_HOURS` | How long a browser stays let in; default 24.
| `PORTER_IDLE_HOURS` | How long a session stands with no wire on it and nothing through the door before the porter ends its process; default 24. The state directory stays.
| `PORTER_TOKEN_DAYS` | How long a door token lives from its minting; default 30. A fixed horizon, never slid by use: a leaked key in steady use still ends, and every script is re-blessed by a human on the day.
| `PORTER_TOKENS_FILE` | The token store; default `<PORTER_STATE_DIR>/tokens.json`, beside the session directories, owner porter, mode 0600. Hashes and names only.
| `PORTER_SOUNDS_DIR` | Optional. A folder of sounds served in place of the page's own: a request for `/s/<key>/sounds/<name>.mp3` (or `.wav`, `.ogg`) is answered from here when the file is there, by bare file name only, and proxied to the session otherwise. For the original LCARS beeps, which TheLCARS.com's licence forbids redistributing and so never ship in a package; kept outside the install, an upgrade does not take them away.
|===

== A terminal through the door

Once, on a terminal:

[source,sh]
----
chell auth login --door https://titan.tch.harvard.edu/
----

It asks how: a web browser (the default; a code to enter on this door's login page, from any device, so the password never crosses the terminal), a password typed here, or a token minted elsewhere pasted in. The token lands in `~/.config/chell/doors/titan.tch.harvard.edu.json` at mode 0600 and the door becomes the default. After that, with no flags:

[source,sh]
----
chell                       # interactive, through the door
chell -c "ls /proc/jobs"    # a script's line, through the door, no password anywhere
chell auth status           # who you are at the door, how long the token lives
chell auth logout           # revoke the token at the door and remove the file
----

`chell --remote --door <url>` is the long form; `--no-door` asks for the local chell anyway, and a `user@url` target still names a CUBE directly. The user's side is in link:../../../packages/chell/docs/login.adoc[chell's login document].

== Door tokens

A door token is how a script comes through without a password: minted once by a human login (the browser code, or a password), kept by the door only as a SHA-256 hash with a name the operator can read (`chris@pangea`, `nightly@pangea`), the identity it is for, when it was minted and when it dies. Presented as `Authorization: Bearer …` on `POST /login`, it is let in the way a password would be, and the ordinary session cookie follows.

* **It dies on its day.** `PORTER_TOKEN_DAYS` (30) from its minting, whatever its use; chell says so from seven days out on every call, and refuses plainly at expiry with the words to run. A `login` again on the same host replaces the old token, so the store never fills with forgotten keys.
* **Minting needs a human.** A token is minted by a password login (a JSON login with `tokenName`, or the login page with a device code), or by the operator on the host: `porter --mint <user> --name <name>` prints the plaintext once, for a service identity or a hand-over. A token never mints a token.
* **Revocation is by name.** `porter --tokens` lists them with last use; `porter --revoke <user> [<name>]` ends one or all of a user's; `chell auth logout` revokes the one in hand. The running door re-reads the store when the file changed under it, so a revocation from the command line is refused on the token's next call without a restart.
* **The journal says.** `[+] <user> came through by door token "<name>"`, `[+] minted a door token "<name>" for <user>`, `[+] refused a door token nobody holds`, `[+] refused <user>'s door token "<name>": it expired on <day>`, so script traffic reads apart from a person at a keyboard.
* **Never over plain http to another host.** Chell refuses to send a token to an `http://` door that is not loopback unless told `--insecure-door`; this door is behind Caddy TLS, and a door that is not should be.
* **Nothing on the command line.** The token is in the user's 0600 file, or in `CHELL_DOOR_TOKEN` for a runner that injects secrets; a password belongs on no command line and in no script (`-p` is honoured and discouraged).

== Running it

`porter --tokens`, `porter --revoke <user> [<name>]` and `porter --mint <user> --name <name>` manage door tokens (above). `porter --version` (`-V`) prints the door's version and the session code it serves (brasa, calypso, chell): what a login would put a daemon on, so whether an older session restarts. `porter` starts the door; `porter --end <who>` ends one session by berth key, identity or user (its state kept; the next login boots on this porter's kernel); `porter --status` lists the sessions the state directory holds — key, identity, address, and whether each answers — without starting anything, and asks for nothing but `PORTER_STATE_DIR` (the CUBE, the port and the secret belong to a door, not a listing).

== Deploying on titan

link:../deploy/porter.service[`deploy/porter.service`], link:../deploy/porter.env.example[`deploy/porter.env.example`] and link:../deploy/Caddyfile[`deploy/Caddyfile`]. A `porter` system user owns `/var/lib/porter`; the unit reads `/etc/porter.env` (mode 0600, it holds the secret) and starts `node /opt/mise/apps/porter/dist/porter.js` on loopback; caddy holds the certificate for `titan.tch.harvard.edu` and proxies to it, WebSockets included. `KillMode=process` keeps sessions alive across a porter stop; the porter adopts them at its next start. The state directory must be on real disk: a session's first boot on this host is the cold one.
